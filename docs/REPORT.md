## 1. Главная приёмка

**Целый трек из Strudel играет в Godot от начала до конца.**

Файл `examples/full_track/kuvshinka.js` — настоящий трек: стек из десяти
партий, форма из шестнадцати секций, аккордовый круг из восьми аккордов,
свинг `23/800`, вероятностное прореживание, эффекты. Вставлен **без единой
правки** — тот же текст, что в браузере.

```
[трек] событий 2449 за 64 циклов
[трек] сборка паттерна 25.0 мс, выборка событий 54.35 мс на цикл
[трек] темп 0.3167 цикла в секунду, длительность 202.1 с
[сверка] проверок 1: совпало 1, расходится 0
```

**2449 событий из 2449** совпали с живой Булкой: те же доли времени точными
дробями, те же ноты, те же громкости побитово.

🔴 **Попутно найдена ошибка в самом треке.** Строка
`ch.rootNotes(2).note().add(note(11))` бросает `cannot parse as numeral`:
`rootNotes` уже отдаёт `{note: "C2"}`, а повторный `.note()` вкладывает
значение само в себя. `queryArc` глотает исключение — поэтому в Булке молчал
**весь трек**, а не одна партия. Лишний `.note()` убран.

## 3. Замер выбора технологии

ТЗ требует решить замером, а не вкусом.

**Замерено** (`tools/bench_audio.gd`, RTX 4090, 48 кГц):

| голосов | своё сведение на GDScript | доля реального времени |
|---:|---:|---:|
| 16 | 70.7 мс на секунду звука | 7.1% |
| 32 | 142.0 | 14.2% |
| 64 | 280.5 | 28.1% |
| 128 | 480.2 | 48.0% |

**Решение: GDScript-аддон со своим сведением.** Причины, в порядке весомости:

1. Штатная `AudioStreamPolyphonic` дешевле (сведение в C++), но **не умеет
   панораму на голос** — это уже выяснено в Osmo (`music.gd:530`), а `pan` в
   Strudel параметр события. И не даёт пер-голосовых фильтров, а `lpf`, `vowel`,
   `crush` — тоже параметры события.
2. Своё сведение укладывается: 32 голоса — 14% одного ядра.
3. GDExtension потребовал бы бинарников под каждую платформу и сломал бы
   установку из Asset Library. Чистый GDScript ставится копированием папки и
   работает всюду, где работает Godot, — что и подтвердилось на Web.

**Цена решения** названа честно: выше 64 голосов сведение съедает четверть
ядра. Место для будущего GDExtension обозначено — это один цикл в
`StrudelVoice.render`, всё остальное от него не зависит.

Отдельно замерена цена самого горячего цикла: пока огибающая, биквад и
источник были **отдельными методами**, голос обходился вшестеро дороже —
вызов функции в GDScript стоит больше самой арифметики. После развёртывания в
тело функции рендер трека ускорился с **32.2% до 10.8%** реального времени.

## 4. Расхождения со Strudel — числами

Эталон снят офлайн-рендером **самой Булки** (`renderPatternAudio`,
OfflineAudioContext), сверка — `tools/judge/check_effects.sh`.

### Совпало точно (0.00 дБ во всех полосах)

синус · громкость · `crush` · `coarse` · `shape` · `pan` · ADSR · `decay`

### Совпало с названной разницей

| узел | СКЗ | причина |
|---|---:|---|
| пила | +1.40 дБ | WebAudio строит её **ограниченной по полосе**, плагин — напрямую с PolyBLEP |
| меандр | +1.42 дБ | то же |
| `lpf(800)` | +1.26 дБ | наследует разницу пилы; на синусе фильтр даёт 0.00 дБ |
| `hpf(800)` | +0.80 дБ | то же |
| `bpf(900)` | +1.40 дБ | то же |
| `vowel("a")` | +1.44 дБ | то же |
| треугольник | −0.00 дБ СКЗ, −9.76 дБ верхняя полоса | не ограничен по полосе; гармоники спадают как 1/n² |

**Положение ударов: 0.00 мс.**

### Порядок цепи подтверждён

`crush(4).lpf(800)` и `lpf(800).crush(4)` дают **одинаковые числа**
(+1.82 дБ, +3.22 худшая полоса). Так и должно быть: порядок задан жёстко в
`superdough`, а не порядком вызовов. Совпадение обеих записей с эталоном
означает, что порядок в плагине тот же.

### Расхождение генератора случайных чисел — НЕТ

Перенесён режим `legacy` (`signal.mjs:601`) — тот, что в Strudel по умолчанию.
`rand`, `irand`, `perlin`, `degradeBy` совпадают **бит в бит**; `degradeBy`
выбрасывает ровно те же события. Режим `precise` не перенесён.

### Три расхождения, которые сверка нашла и которые устранены

Все три на слух не ловятся, а замером видны сразу:

1. **Синтез в Strudel приглушён на 0.3** (`synth.mjs:54`, комментарий
   «turn down»). Без этого плагин был на **+11 дБ** громче эталона.
2. **У синтеза своя огибающая по умолчанию** — `[0.001, 0.05, 0.6, 0.01]`, а не
   общая `[0.001, 0.001, 1, 0.01]`.
3. **Панораматор вставляется ТОЛЬКО когда `pan` задан** (`superdough.mjs:898`).
   Постоянная равномощная панорама давала ровно **−3.01 дБ по всем полосам**.

### Ещё две находки в поведении оригинала

- **`.add(7)` на управляющем паттерне НИЧЕГО не делает.** `unionWithObj`
  (`value.mjs:12`) бросает «Can't do arithmetic on control pattern» и
  возвращает левое значение. Девять проверок разошлись, пока я честно
  складывал.
- **`swingBy(0.23, 4)` требует, чтобы `0.115` стало ровно `23/200`** — через
  последовательности Фарея, как в `fraction.js`. Через двоичную дробь свинг
  уезжает.

### Реверберация — другой алгоритм

Strudel сворачивает с импульсным откликом (`reverbGen.mjs`), плагин — схема
Шрёдера (четыре гребенчатых, два всепропускающих). Свёртка на GDScript
обошлась бы дороже всего остального. Хвост близок, но **не тождествен**, и
числом не сверялся.

## 6. Интеграция Osmo

Плагин поставлен в игру, весь код, знающий про игру, — в одном файле.

```
[связка] наборов в банке: 266
[связка] событий сыграно: 5, пик звука: 0.0319
[связка] trim набора "vsco-solo-contrabass__pizz": +21.1 дБ
[связка] в плагине нет ни одного упоминания Osmo — граница цела
[связка] ИТОГ: пройдено 4 проверок
```

Гейты самой игры:

```
[flow]  ИТОГ: ВСЁ ЗЕЛЕНО (провалов 0)
[обход] ИТОГ: шагов 11, бед 0
```

Все одиннадцать жанров играют как играли. `git diff --stat -- drop/styles.gd`
**пуст**.

**Кто выравнивает громкость — решено явно:** это делает игра. `trim` из описи
банка остаётся в `drop/strudel_bridge.gd`, потому что банк собран под игру и
чужому проекту эта поправка не нужна. В плагин он не попал.

**Проверка границы:** поиск по всей поставке `addons/strudel` не находит ни
`res://audio/bank`, ни `styles.gd`, ни `music.gd`, ни `gu.sf2`, ни слова
«Osmo». Удалять из плагина нечего — значит граница проведена верно.

Перевод одиннадцати треков из `drop/styles.gd` в код Strudel — **следующая
задача**, в эту не входила.

## 8. Готовность к публикации

Что сделано:

- `addons/strudel/` с `plugin.cfg`, 59 файлов, 418 КБ, без внешних зависимостей;
- `README.md` и `README_RU.md` по скиллу оформления: центрированная шапка,
  бейджи `flat-square`, скриншот, golden order секций, блок про Strudel со
  ссылками на strudel.cc и bulka.app;
- `docs/SYNTAX.md` — что есть, чего нет, что иначе;
- `docs/COMPARISON.md` — расхождения числами;
- `docs/PORTING-RULES.md` — правила переноса;
- `NOTICE.md` — происхождение и смысл лицензии;
- `LICENSE` (AGPL-3.0), `CHANGELOG.md`, `.github/FUNDING.yml`;
- `examples/` — минимальный бит, реакция игры, целый трек, свой банк;
- тесты (225 сверок) и CI, который гоняет тесты, сверку событий, главную
  приёмку и установку с нуля.

Чего не хватает для выкладки:

1. **Ничего не опубликовано** — по указанию. Репозиторий не создан, ничего не
   отправлено.
2. **Лицензия AGPL-3.0** — это не выбор, а следствие: плагин порт Strudel.
   Решение, публиковать ли на таких условиях, за автором. Для Osmo это
   означает, что распространение игры вместе с плагином подводит игру под
   AGPL. Подробности — `NOTICE.md`.
3. Social Preview 1280×640 не сделан.
4. Star History по скиллу требует своего Action — не заведён.
5. Для Asset Library нужны: репозиторий на GitHub, тег версии, иконка.
6. Комментарии в коде на русском. Для международного плагина это барьер
   контрибуторам; решение оставить их принято по стилю остальных репозиториев
   автора и вынесено сюда явно.

## 9. UNVERIFIED — что осталось непроверенным

Без слова «исправлено».

- **Android**: экспорт не собрался — в этой машине не настроен Android SDK.
  Плагин на чистом GDScript и платформенного кода не содержит, но это довод, а
  не проверка.
- **Linux**: сборка собирается (73 МБ), запустить негде.
- **Звук целого трека против Булки**: Булка играет его сэмплами из карт,
  ссылающихся на сеть; локально их нет. Сверены только события.
- **Отсутствие щелчка** при живой замене: проверено, что такт не сбрасывается и
  звучащие голоса доигрывают. Сам щелчок акустически не измерялся.
- **Хвост ревербератора** числом не сверялся.
- **Отсутствие звуковой карты**: офлайн-рендер работает без устройства вывода,
  но поведение `AudioStreamPlayer` при полном отсутствии драйвера не проверено.
- **Утечка ссылок**: при выходе Godot сообщает о ~2900 неосвобождённых
  объектах. Это циклы ссылок в замыканиях паттернов. На работу не влияет, но
  при многократной замене кода память будет расти — не измерено.
- **Не перенесено** (перечислено в `docs/SYNTAX.md`): `distort`, `tremolo`,
  `compressor`, `phaser`, огибающие фильтров, FM, супер-пила, вейвтейблы,
  `partials`, отдельные шины по `orbit`, семейство `slice`/`splice`/`fit`,
  stepwise-функции `take`/`drop`/`grow`/`shrink`, режим случайного `precise`.
- **ogg и mp3** как источники сэмплов: Godot не отдаёт из них PCM в GDScript.
  Пак переводится заранее (`tools/convert_samples.py`), сам инструмент на
  настоящем паке не прогонялся — ffmpeg в этой машине не проверялся.

## 10. Команды, которые действительно запускались

```bash
# тесты плагина
bash tools/test.sh
# → [тесты] проверок 225, случаев 55, бед 0

# сверка событий с эталоном Булки
godot --headless --path . --script res://tools/judge/run_corpus.gd
python tools/judge/compare.py
# → совпало 115, расходится 0, обе стороны отказались 1

# главная приёмка
godot --headless --path . --script res://tools/judge/run_track.gd
python tools/judge/compare.py --track
# → совпало 1, расходится 0

# сверка звука по узлам цепи
bash tools/judge/check_effects.sh

# уход долей
godot --headless --path . --script res://tools/check_drift.gd

# установка с нуля в пустой проект
bash tools/check_clean_install.sh

# саундфонт
godot --headless --path . --script res://tools/check_soundfont.gd -- --sf2=<файл>

# вывод в файл без звуковой карты
godot --headless --path . --script res://tools/render_wav.gd -- \
      --file=res://examples/full_track/kuvshinka.js --out=<файл> --seconds=60

# экспорт и ЗАПУСК собранного
godot --headless --path . --export-release "Windows Desktop" build/StrudelDemo.exe
./build/StrudelDemo.exe

# связка с игрой и её гейты
godot --headless --path <игра> --script res://tools/check_strudel.gd
godot --audio-driver Dummy --path <игра> -- --flowtest
godot --audio-driver Dummy --path <игра> -- --sweep
```
